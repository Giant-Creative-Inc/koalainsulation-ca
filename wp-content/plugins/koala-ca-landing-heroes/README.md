# Efficiency landing page — staging preparation

This package ports the approved Local Efficiency preview into a **new, dedicated Bricks template** and a separate preview landing page. It does not edit shared template 20847, other landing pages, shared classes, Gravity Forms, location credentials, cache rules, or the existing location router.

It includes all six compressed WebP heroes, fonts, scoped responsive CSS, the approved generic content and five service links, the corporate review helper, ACF page content, and supporting media. Review feed contents remain the destination site's existing corporate feed; no review or customer database is imported.

## Safety and prerequisites

- Runtime and installer are blocked unless `wp_get_environment_type()` is `local` or `staging`. Set the real environment in the host configuration; do not mark production as staging.
- Activating the plugin alone makes no page/template/database content changes. It remains inert until preparation is applied.
- Require Canadian Bricks routing, ACF, Gravity Forms form 1, the corporate Google Reviews feed, and a published location whose exact slug is `efficiency`. `efficiency-2` is not substituted.
- Destination services resolve by their exact slugs; global classes resolve by name; media resolve by upload path or are imported from the bundled files. Missing/ambiguous dependencies stop preparation.
- Run WP-CLI as the site's owner and specify an existing administrator with Bricks code execution permission using `--user`. No security checks are disabled.
- Back up staging's database and uploads before applying. The installer also saves its own page metadata/status recovery snapshot and a fingerprint of shared template 20847.

## Deployment boundary

Deploy this feature branch to **staging only** using the normal hosting workflow. The change includes a one-line guard in `wp-content/themes/bricks/assets/js/custom/all-pages.js`; it must be deployed together with this plugin. Only the configured Efficiency page sets that guard. All other pages retain the existing navigation behaviour.

No staging or production deployment has been performed as part of preparing this branch.

## Commands

Run from staging's Canadian WordPress root with the appropriate `--user` set in the WP-CLI invocation. Commands below use the normal `wp` launcher. All commands reject a production environment.

```sh
wp plugin activate koala-ca-landing-heroes
wp koala-efficiency prepare --route-prefix=/ca
```

The second command is a **read-only dry run**. Review its resolved IDs, dependencies, and route. The default preview slug is `efficiency-ad-preview`, so the existing `awesome-test-page` or another franchise's page is not reassigned.

After the dry run is clean:

```sh
wp --user=23 koala-efficiency prepare --route-prefix=/ca --apply
wp koala-efficiency verify
```

`23` is the Local administrator ID; resolve and use the staging administrator's actual ID before running apply. An existing page may be used with `--page-slug=...` only when it is already related to Efficiency. A page belonging to another location is rejected. Repeating apply after a successful installation does not overwrite editor changes.

The resulting staging route is:

```text
/ca/efficiency/landing-pages/efficiency-ad-preview/?hero=ice-storm
```

The installer resolves destination IDs and generates fresh IDs for **every** copied element. Bricks template conditions contain only the new preview page ID. Destination code signatures are generated by WordPress. The earlier Local template condition/duplicate-Code-ID regressions are explicitly checked by `verify` and the tests.

## Staging acceptance checks

1. Run `verify`. Confirm shared template 20847 remains unchanged, the dedicated template has only the preview page condition, and all element IDs/signatures pass.
2. Open the Efficiency route with no query, an unknown `hero`, and each of `cold-outside`, `cold-home`, `icicles`, `snowstorm`, `strong-winds`, `ice-storm`. Default/unknown queries keep the original hero. Test mobile, tablet and desktop, form shadow, copy spacing, accordions, five service destinations and corporate reviews.
3. Check corporate header/footer links after JavaScript runs. They must not change to `/efficiency/...` navigation links. The underlying lead context must still be Efficiency.
4. Inspect the form's existing location/SM/HCP routing data and integration settings. The custom router already selects the location context before loading the header. This plugin does not replace it. **Do not send an end-to-end lead until staging CRM/email recipients and the test destination are approved.** No successful submissions were sent during preparation.
5. Open all other published landing pages, especially the Halton renovation-contractors, home-builders, home-service-provider, partners and attic-rebate pages. Check their original heroes/forms, page-specific accordion content, testimonials and menus. Add `?hero=ice-storm`: it must not opt them into the campaign.
6. Check the same landing slug under an unrelated location: the existing router should reject it. Confirm Efficiency's relationship uses the destination Efficiency ID, not a Local ID.
7. Test anonymous requests with caches cold and warm: `hero` variants must not share cached HTML. Keep tracking parameters alongside `hero`. Check hosting page cache and CDN separately; this package makes no cache-rule changes. A variant cache mismatch blocks release until the staging host's query-cache policy is corrected.
8. Confirm the chosen route has one appropriate canonical URL and no accidental indexation during staging testing. Existing routing/canonical behaviour is preserved and must be checked on the host.

Local routing is known to differ from staging. Local dry-run and unit checks do **not** establish that hosting routing, cache variation or CRM lead delivery work.

## Rollback

```sh
wp koala-efficiency rollback
wp koala-efficiency rollback --apply
```

Rollback defaults to a dry run. Applying restores the managed page's previous metadata/status (or drafts the newly created preview), disables campaign configuration and drafts the dedicated template. It does not touch template 20847 or other landing pages. Imported media are retained for safe recovery; they are not automatically deleted. Run rollback after a partial apply before retrying preparation. The plugin can then be deactivated. Keep the hosting backup until acceptance is complete.
